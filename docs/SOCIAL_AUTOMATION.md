# 物件からSNS投稿を作る

公開物件の文章・画像を作成し、Instagram・Threadsへ予約します。文章は登録済みの情報から生成します。AI契約や追加の文章生成サービスは必要ありません。管理画面からの手動予約に加えて、自動運転を利用できます。

## 自動運転（2026-10-13追加）

- 水・金・日20:00（日本時間）に1物件を両SNSへ予約。直近の予約枠を朝6時ごろに補充します。夜19時ごろは結果確認のみです。Vercelの実行時刻には幅があります。
- `social_autopilot_settings.enabled` が有効で、登録された2つのチャンネルIDだけに送信します。新しいチャンネルを自動的に選ぶことはありません。
- 公開中・掲載承諾と確認日あり・メイン写真あり・予約日まで次回更新期限内の物件が対象。最新の情報確認日順に選びます。
- 過去にこのサイトから予約処理した物件は自動で繰り返しません。直近30日分のBuffer履歴も照合し、物件名・物件URLの重複や、同じ日の既存投稿があれば追加しません。
- `social_autopilot_slots` の一意制約とトランザクション、投稿先ごとの送信権取得で同時実行・再実行の二重送信を防ぎます。
- `social_deliveries.status=scheduled` は予約受付。実際の公開結果は `provider_status=sent`、公開日時は `published_at`、公開URLは `published_url` です。確認失敗時は最終既知状態を残し、`provider_check_error` を記録します。
- 実行記録は `social_autopilot_runs`。朝夕のチャット報告は最新の実行日時・結果を読み取ります。取得できない状態は未確認として扱います。
- 投稿失敗・結果不明・接続切れ・候補不足は報告し、むやみに投稿を増やしません。自動再送はせず、原因を解消して実際の予約・公開状態を確認してから対応します。
- 自動予約は人の都度確認を表さないため、`confirmed_by` / `confirmed_at` はNULLのままです。

### 稼働設定

1. `20261012193000_social_autopilot.sql` を適用（既定では無効）。
2. Vercel Production にランダムな32文字以上の `CRON_SECRET` をSecretとして保存。既存の `BUFFER_API_KEY` をそのまま使用します。
3. 管理者が確認したチャンネルIDを `social_autopilot_settings.channel_ids` に保存。
4. 本番をデプロイし、認証付きの `/api/cron/social?mode=monitor` で接続・投稿結果・候補を確認してから `enabled=true` にする。
5. 認証付き `/api/cron/social` で初回予約を確認。公開結果は次回以降の確認で判定する。

停止は `social_autopilot_settings.enabled=false`。これは新規の自動予約を停止します。Bufferに受付済みの予約は取り消されません。秘密キーはチャット・GitHub・公開URLに載せません。

物件の実際の空き状況や写真使用許可を外部から自動確認する機能はありません。登録情報が根拠です。予約後の募集終了・条件変更は現時点では自動編集・取消されないため、既存の予約をBufferで変更してください。

## 初回のみ

1. [BufferのAPI設定](https://publish.buffer.com/settings/api)で接続キーを作成します。使用する組織・チャンネルの読み取りと投稿作成を許可してください。
2. Vercelのこのサイトのプロジェクト → Settings → Environment Variablesに、名前 `BUFFER_API_KEY`、種類 **Secret**、対象 **Production** として保存します。キーはチャットやGitHubに貼らないでください。`NEXT_PUBLIC_` は付けません。
3. Productionを再デプロイし、[SNS投稿画面](https://garagehouse-navi.com/admin/social)の「Bufferの投稿先を読み込む」で、正しいInstagram・Threadsアカウントが表示されることを確認します。

キー未設定でも投稿案・画像の作成、文章編集、下書き保存、コピーは利用できます。実際のアカウント名と予約結果を確認できるまでは、接続完了とはしません。

開発者は `supabase/migrations/20261010143257_social_composer.sql` を先に適用してください。投稿案・送信履歴と非公開の画像保存先を追加します。既存物件・問い合わせは変更しません。

## 毎回の操作

1. 公開物件を選んで「投稿案と画像を作る」。物件の編集画面からも移動できます。
2. 賃料・管理費・写真・募集状況・写真のSNS掲載許可を確認し、文章を編集します。
3. 投稿先を読み込み、Instagram・Threadsのアカウントを選びます。日本時間で投稿日時を指定し、確認欄にチェックして予約します。
4. 投稿先ごとの「Buffer予約済み」と予約IDを確認します。指定時刻後、Bufferと実際のSNSでも公開を確認します。予約受付は公開完了の証明ではありません。

掲載承諾と確認日、メイン写真、次回更新予定日の登録が必要です。予約日は次回更新予定日まで、かつ現在から5分以上先・30日以内です。画像はメイン写真全体を保持した1080×1350のJPEGです。Instagramは物件名を添えてプロフィールのサイトへ、Threadsは物件詳細URLへ誘導します。

**予約後の物件変更は投稿に自動反映されません。** 募集終了や賃料変更があれば、[Buffer](https://publish.buffer.com/)で予約を編集・取り消してください。同じ物件情報の投稿案は再利用します。別の日に再投稿する場合はBufferで内容と募集状況を確認して操作してください。

## エラー時

| 表示 | 対応 |
| --- | --- |
| 接続キー未設定 | 上記の初回設定と再デプロイを行う |
| 投稿先を選べない | Bufferでアカウント再接続・停止解除・プラン上限を確認 |
| 掲載承諾・更新予定日の確認 | 物件管理で実際の確認結果を保存し、投稿案を作り直す |
| 予約できませんでした | 接続や予約上限を確認し、「未送信・失敗した分だけ再試行」 |
| 結果を確認中／Bufferで確認が必要 | 自動再送しない。Bufferの予約一覧で同じ物件・日時を確認する |

タイムアウト後に予約が成立している可能性があるため、結果が不明な投稿は再送を停止します。成功した片方は再送しません。画面を再読み込みして履歴を確認できます。結果不明を解消できない場合は開発担当がBufferの予約と履歴を照合してください。

## 実装・確認範囲

- 管理者認証と同一オリジン検証。一般ユーザーは投稿案・予約履歴を取得できません。
- 予約確定時の文章・投稿先・日時・確認者をDBへ同時に保存し、送信前の排他的な状態変更で重複送信を防止します。
- Bufferの接続キーはサーバー内だけで使用します。非公開画像の確認URLは30分、Buffer向けURLは35日有効です。予約期間を30日以内に制限しています。
- テストではBufferの送信を模擬し、日時・投稿先・文字数・重複・部分失敗・通信結果不明・DB権限を確認しています。実キー設定後の予約とSNS公開は別途確認が必要です。
- `npm test`、`npm run typecheck`、`npm run build`。画面は `node scripts/social-browser-check.mjs` でローカルの架空データと模擬送信を使って確認します。
